# API 配置与验证手册

## Mock 模式（默认、推荐主舞台使用）

```text
DATA_MODE=mock
```

不需要任何密钥，输出固定可复现，并在报告中显示“缓存降级”。

## DeepSeek V4 Flash 实时模式

在 `.env.local` 或 Vercel 服务端环境变量中配置：

```text
DATA_MODE=live
AI_PROVIDER=deepseek
DEEPSEEK_API_KEY=sk-...
AI_MODEL=deepseek-v4-flash
NEXT_PUBLIC_SITE_URL=http://localhost:3000
```

重启开发服务器后，从首页完整走一遍。检查报告顶部不再显示 Mock 提示；如果联网搜索失败，允许报告显示缓存降级，但提问与报告生成仍应完成。

DeepSeek 实现有两类请求：

- `/chat/completions`：结构化生成三道题、报告和分享草稿。
- `/anthropic/v1/messages`：按 DeepSeek 官方 Harness 方式调用 `web_search_20250305` 服务端工具。

项目没有单独的 SearchProvider，也不会把 API Key 发往浏览器。

报告生成成功后，前端会对三个职业方向依次调用 `POST /api/job-verification`。该接口沿用同一个 provider 的搜索能力，先把报告方向与内置英文市场别名合并，再生成同义方向与相邻起步岗，并行执行分层搜索；画像明确为应届、学生或无正式经验时，检索会加入实习、校招、助理、graduate、junior、associate 等阶段词。国际候选通过 Greenhouse、Lever、Ashby、SmartRecruiters 或 Workday 官方公开接口二次确认。国内岗位采用两条互补链路：旧版北森详情页仍要求受限路径、同域申请入口和当前申请按钮；新版北森企业租户则通过公开 `GetJobAdPageList` 接口按中文职位词扩展岗位，只接受接口当前返回、`Status=1`、GUID 完整、未明确过期且地区/招聘阶段相容的记录。高校就业网、求职平台和搜索摘要仅用于发现企业租户与岗位线索，不作为最终投递链接。它不会延长主报告等待时间。

若北森企业官网因部署网络原因未完成直连核验，接口可以附带最多 3 条 `leads`：仅接受已通过北森官方域名/固定详情路径解析、搜索证据仍带“申请职位/我要申请/立即申请”、没有明确关闭文案、且岗位名称能确定性归入目标/同义/相邻方向的结果。它们不会进入 `jobs`，不标记“核验时仍在招”，前端只在“资料有出处，岗位有时效”来源网格中显示为“企业官网机会 / 待打开确认”。

DeepSeek 原生搜索参数对齐 `deepseek-ai/deepseek-harness`：单次核验请求最多使用 5 次 `web_search_20250305`，`max_tokens=4096`。应用层每条查询最多接收 6 个结果、每个方向最多读取 8 个官方候选；其中北森详情候选最多保留 4 条，并可从最多 2 个安全北森企业租户的公开职位列表补充最多 4 条结构化候选。扩大的是官方候选发现范围，不会绕过状态、地区、阶段和匹配核验。五层查询分别覆盖国际目标岗、国际同义岗、国际相邻岗、国内精确中文职位词、国内相邻起步岗。

## OpenAI 备选模式

```text
DATA_MODE=live
AI_PROVIDER=openai
OPENAI_API_KEY=sk-...
OPENAI_MODEL=gpt-5-mini
NEXT_PUBLIC_SITE_URL=http://localhost:3000
```

OpenAI 使用 Responses API；职业资料检索使用同一 provider 的 `web_search` 工具。

## 验证通过标准

- 画像提交后返回恰好 3 道初始题。
- 第 3 题之后只出现 1 道动态第 4 题。
- 报告恰好包含 3 条路径，顺序为夯、稳、拉。
- 每条路径都有证据账本、缺口、现实代价和七天任务。
- 实时资料有可打开链接；失败时明确显示缓存来源/缓存降级。`live-1` 等值只是服务端内部关联 ID，页面必须映射为来源标题和发布方，不得直接展示给用户。
- 报告出现后，三个岗位方向分别显示等待、核验中、完成或失败状态，单方向失败不影响报告和其他方向。
- 只有受支持 ATS 的官方 API 仍返回岗位、官方申请入口存在、且当前已知地区/方向/阶段无明确冲突时，页面才显示“核验时仍在招”。未知条件必须作为“投递前仍需确认”展示。
- Mock 模式不返回虚构岗位；Live 模式没有通过双重核验的候选时展示空状态。
- 同义方向和相邻起步岗必须显示 `searchTier` 与 `expansionReason`；排序固定为目标岗位优先、同义方向其次、相邻起步岗最后。扩大的是候选发现范围，不降低官方在招、地区、阶段和申请入口核验标准。
- 个性化题目降级时，响应包含安全的 `fallbackReason.code` 与 `fallbackReason.label`；页面显示简短原因并继续提供通用题。
- API 错误不返回密钥、完整模型原文或服务器堆栈。

## 常见问题

**提示缺少 API Key**：确认环境变量名正确，并在修改后重启本地服务或重新部署 Vercel。

**DeepSeek 搜索失败但报告成功**：这是设计内的降级。检查 `/anthropic/v1/messages` 对当前账号/模型是否开放，以及余额、限流和网络。

**输出结构不合法**：服务端会自动重试一次；仍失败则返回安全错误。现场切回 `DATA_MODE=mock`。

**出现“个性化问题生成未完成”**：题目生成已安全降级，不代表流程中断。页面会区分 AI 响应超时、服务繁忙、连接异常、返回格式异常、配置不可用或服务暂时不可用；用户可以继续回答通用题。服务端只记录 `requestId`、阶段、provider、错误码、是否可重试和耗时，不记录画像、模型原文或密钥。

**请求超时**：题目/候选发现/贡献草稿单次尝试 20 秒，单方向搜索单次尝试 18 秒，最终报告单次尝试 40 秒；可重试阶段最多重试一次。浏览器请求上限 125 秒，服务端整体硬截止 120 秒，Vercel 函数上限 150 秒。之所以分成 125/120/150 三层，是因为 2026-08-22 的 Live Preview 报告实测达到 75.7 秒；延长应用余量可以吸收 DeepSeek/Harness 网络抖动，同时让服务端有机会在平台强制终止前返回结构化超时错误。不要在现场反复点击生成。

**岗位核验超时**：每个方向独立执行，国际 ATS 单次读取上限 8 秒、北森旧页 18 秒、北森公开列表 12 秒，岗位匹配生成上限 16 秒，服务端整体 60 秒、浏览器 65 秒、Vercel 75 秒。失败卡片可单独重试，不需要重新生成主报告。

## 安全要求

- 永远不要把 Key 写进源代码、截图、前端环境变量或聊天记录。
- `.env.local` 已被 Git 忽略；只提交 `.env.example`。
- 轮换任何曾公开展示或误提交的 Key。
- Production 的两个收费端点采用三层前置门禁：严格同源 / Fetch Metadata 校验、Vercel BotID Basic 无感浏览器验证、可信 `x-vercel-forwarded-for` 客户端地址的单实例突发限流。三层均位于 JSON 解析、联网搜索和模型调用之前。
- BotID Basic 对所有 Vercel 套餐免费。正常用户从页面操作不会看到验证码；直接 `curl`、Node/Python 脚本或没有完成页面挑战的请求应返回 HTTP 403、`REQUEST_BLOCKED`，且不得调用 DeepSeek。
- 本地开发默认由 BotID SDK 放行，便于 Mock 调试；不能用本地直连结果证明 Production 防护有效。每次安全相关部署必须同时验证“正式页面正常生成”和“正式 API 直接脚本返回 403”。
- 当前内存突发限流用于限制单个热实例内的短时重放，不可冒充跨实例全局配额。若升级 Vercel Pro，可在观察日志后为两个 POST 路由增加 WAF Rate Limit；正式拦截前必须按 log → Preview → Production 分阶段发布。
- 不要给收费端点配置宽泛的 BotID/WAF bypass。确需可信自动化时，必须同时使用不可猜测的服务凭证和固定来源网络，并单独评审。
- 真实用户数据进入正式产品前必须增加持久化加密、删除机制、审核权限和隐私政策；本 Demo 不声称已具备这些能力。
