# SSAI 黑客松演示脚本与评分对照

## 一句话定位

职途罗盘帮助“经历还不够标准、尤其没有正式实习”的学生，把一段真实项目经历转成三个有证据、能比较、可在七天内验证的职业方向。

## 5 分钟演示脚本

### 0:00—0:35｜问题

“很多职业测评会先给人一个标签，再给一串岗位名。但对缺少正式实习的学生，真正缺的不是另一个标签，而是：我做过的事说明了什么？哪些结论是证据，哪些只是推断？下一步如何低成本验证？”

首页停留在三条原则：从真实经历出发、三视角交叉观察、把结论变成行动。

### 0:35—1:10｜输入

点击“使用示例画像快速体验”。强调：课程、社团、校园与个人项目都能成为证据；系统主动提示不要填写姓名、联系方式、公司机密和他人隐私。

快速指向时间、预算、地区等现实约束，说明路径排序不仅看兴趣。

### 1:10—2:05｜AI 提问

进入四轮探索。前三题来自三种互补视角：如何拆问题、如何配置长期投入、如何理解人的体验。答完第三题后展示动态第四题，说明它不是固定问卷，而是针对证据缺口继续确认。

### 2:05—3:30｜报告核心

生成报告后先解释“夯 / 稳 / 拉”是验证顺序，不是人的高低：

- 夯：当前证据最支持，先投入七天。
- 稳：存在匹配，但还缺关键证据。
- 拉：可迁移但不确定性高，保持探索。

展开“夯”路径，重点展示：匹配理由、真实工作、进入门槛、现实代价、证据缺口。随后指向证据账本的“我的回答 / 导师观察 / 已核验职业事实 / AI 推断 / 检索资料”标签，说明 AI 没有把不同可信度的信息混为一谈。

展示来源卡和七天任务的产出、时间、预算、完成/调整/退出标准。

### 3:30—4:05｜动态岗位核验

指向报告下方逐方向更新的岗位核验区：“报告先给用户看，岗位随后异步核验，所以不让招聘网站拖慢主流程。系统会从目标岗位扩展到招聘市场的中英文同义职位和共享核心任务的相邻起步岗，并明确告诉用户为什么扩展。搜索结果本身不算有效岗位；只有 Greenhouse、Lever、Ashby 或 SmartRecruiters 官方接口确认仍发布、申请入口存在、且当前已知地区和职业阶段没有硬冲突，才显示为‘核验时仍在招’。薪资、签证和用工条件仍提醒用户投递前复查。”

### 4:05—4:35｜安全与失败场景

指出页面的 Mock / 缓存标识：现场默认用可复现结果保证演示；实时模式才使用 DeepSeek V4 Flash 和官方 Harness 原生搜索能力。搜索失败会降级并明示，不会伪造“实时来源”。职业建议需要真实任务、从业者和招聘市场继续核验。

### 4:35—5:00｜价值闭环

点击“分享行业经验”。展示默认不授权、用途说明、草稿可编辑、五项确认和仅本地待审核。解释正式产品可以在人工审核后，把真实行业经验反哺下一位用户；Demo 不上传、不发积分，避免夸大完成度。

结尾：“我们没有替用户选职业，而是让职业选择第一次变成一组可追溯、可证伪、七天内能行动的假设。”

## 评分维度对照

| 评分维度 | Demo 中的可见证据 | 现场表达重点 |
| --- | --- | --- |
| 问题与用户需求 | 无正式实习也可用的经历入口；围绕证据不足与行动困难设计 | 明确目标用户、典型时刻与非测评差异；补充团队在一周内完成的访谈/观察证据 |
| 解决方案与完成度 | 从画像、4 题、三路径、动态岗位核验到七天行动的端到端闭环；Mock 降级可稳定演示 | 不跳步骤；现场完整生成一次；说明测试结果与有意不做的范围 |
| AI 应用合理性 | 个性化提问、动态追问、职业资料检索、证据综合与岗位适配初筛；来源与推断分层，官方 ATS 再确认发布状态 | 解释 AI 负责语义匹配、确定性 API 负责在招事实；主动讲未知条件、人工复查、失败与限制 |
| 创新与项目价值 | 三视角不是人格诊断；“夯稳拉”按证据和约束排验证顺序；七天可证伪任务 | 强调从“推荐职业”转为“管理职业假设”，从结论转为验证 |
| Demo 与表达 | 单页连续流程、可复现示例、响应式、来源和边界均在产品内可见 | 控制在 5 分钟；只演示一个故事；准备 Mock 主链路和实时 AI 备选链路 |

## 评委可能追问

**为什么需要 AI，不用规则问卷？** 真实经历是非结构化的，同一行为在不同约束下含义不同。AI 用于提出与经历相关的问题、综合多源职业资料和解释证据；排序标准、标签、数量、失败降级与行动格式由产品规则约束。

**如何防幻觉？** 把用户回答、导师观察、检索资料和 AI 推断明确分层；资料带可读链接、地区、时间与可信度。岗位搜索结果还要经过官方 ATS 发布状态和申请入口确认，再由 AI 检查与当前已知条件的冲突；任何一层不通过就不展示为可投。最终建议仍是待验证假设。

**“三位导师”是不是模拟名人？** 不是。它们是三种设计好的观察视角，不模仿名人，不做人格诊断。

**你们验证过需求吗？** 只能展示真实完成的证据。建议团队在上台前补一页：访谈人数、用户原话的短摘要、最常见困难、一次可用性测试发现及改动。严禁虚构数字。

**为什么没有账号/支付/积分？** 一周 Demo 优先验证职业探索主链路。高级报告与知识积分仅展示产品路线，界面明确标注“不收费、不发真实积分”。

## 上台前证据清单

- 至少 3—5 名目标用户的简短访谈或可用性测试记录（需脱敏）。
- 一张“原假设—发现—改动”表，证明一周内的学习速度。
- 一次全流程计时录像或现场彩排记录。
- DeepSeek 实时模式的成功截图和失败降级截图；如果来不及完成真 Key 测试，就明确说“代码已接通、尚未完成真实额度验证”。
- 一个手机端和一个桌面端截图。
